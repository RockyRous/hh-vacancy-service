# HH Vacancy Service

Небольшой личный сервис для поиска вакансий на hh.ru, сопоставления с тремя профилями резюме и управляемых откликов с отчётами в Telegram.

**Статус на 30 октября 2026:** реализованы локальный поиск, предварительная оценка, Telegram-команды и расписание без отправки откликов. Автоматическая отправка ещё не реализована.

## Планируемая работа

- Пять обходов в день: 09:00, 12:00, 15:00, 18:00 и 21:00 по Europe/Moscow; сбор сегодняшних вакансий с пагинацией и дедупликацией.
- Объяснимая оценка каждого из трёх профилей правилами без LLM. Порог 50/100 предварительный и требует проверки на размеченной выборке.
- Отсечение по зарплате только при достоверно указанной верхней границе в RUB строго ниже 200 000. Полные правила — в документе решений.
- Выбор согласованного письма, ручная очередь для тестов и форм, защита от повторных откликов и отдельный учёт неопределённых исходов.
- SQLite для снимков, версий, решений, истории и очереди уведомлений; Telegram для отчётов и команд владельца `/on`, `/off`, `/status`.
- По умолчанию hh-работа выключена; `/off` останавливает новые обращения к hh, включая поиск и мониторинг.

## Ближайшие шаги

1. Проверять и уточнять сбор вакансий по трём резюме и распознавание форм на реальных результатах.
2. Подготовить профили, правила оценки и письма, проверить их на нескольких десятках вакансий.
3. Добавить Telegram, расписание и доступную историю откликов; затем реализовать и проверить отправку.
4. Провести согласованный ограниченный автоматический пилот после проверки правил.

Подтверждённого рабочего лимита пока нет. Для будущих испытаний предусмотрено не более 5 откликов за обход и 15 за сутки с дополнительным учётом скользящих 24 часов. Доступность методов hh и ограничения требуют проверки на конкретном аккаунте.

## Структура и запуск

Запуск одного обхода: `python scan.py`. Нужны локальная сессия hh в `~/.codex/hh-session/session.json` и `data/profiles.json` с тремя сопоставлениями направления и ID резюме. На текущем компьютере локальные профили уже настроены. Данные сохраняются в `data/vacancies.sqlite3`, отчёт — в `reports/latest.md`; эти файлы исключены из Git.

Управление: `python service.py` запускает Telegram-бота и расписание. По умолчанию hh выключен; команды владельца `/on`, `/off`, `/status` доступны в личном чате с ботом. `/on` разрешает read-only обходы в ближайшие 09:00, 12:00, 15:00, 18:00 и 21:00 по Москве. `/off` запрещает новые запросы к hh; уже начатый запрос может завершиться. Выключенное состояние сохраняется при перезапуске. Расписание работает только пока процесс запущен и компьютер не спит.

Локальные `python scan.py` и сетевой `python score_run.py` тоже подчиняются состоянию `/on` и общей блокировке единственного процесса: при работающем боте их отдельно не запускать. `python score_run.py --offline` работает без запросов hh, но также требует остановленного бота. Сбой или ограничение hh ставит работу на паузу; после устранения причины нужен `/on`. Очередь Telegram сохраняется в SQLite и доставляется независимо от hh.

Скрипт читает hh, не отправляет отклики, останавливается при ошибках и сохраняет частичный результат. Метка «отсутствие анкеты не подтверждено» означает, что найденные признаки формы отсутствуют, а не что форма точно не нужна. Выдача hh, даже если она связана с резюме, может содержать неподходящие вакансии; предварительная оценка запускается отдельно.

После завершённого сегодняшнего обхода `python score_run.py` получает полные описания, считает три предварительных балла и создаёт `reports/scored.md`. Данные и история переоценок хранятся в той же SQLite. `python score_run.py --offline` пересчитывает уже сохранённые описания без обращений к hh. Правила и порог 50/100 — гипотеза, не вероятность и не основание для автоматической отправки; они требуют ручной проверки на размеченной выборке. Анкеты с неизвестным статусом не считаются проверенными.

`python review_scores.py` строит `reports/review.md` по локальной разметке первой выборки. Для новых выборок её нужно дополнить и проверить отдельно.

Локальные проверки: `python -m unittest discover -s tests -v`. Дополнительные Python-пакеты для первого обхода не нужны.

В Git не добавляются токены, cookies, сессии, резюме, переписка, рабочие базы и локальные отчёты. Репозиторий создаётся приватным; персональные данные остаются вне него.
