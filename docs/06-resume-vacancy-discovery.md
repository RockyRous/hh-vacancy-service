# Поиск вакансий для конкретного резюме — исследование, 28 октября 2026

## Цель и место в плане

До проектирования поискового конвейера проверить и согласовать способ получать свежие вакансии для каждого из трёх рабочих резюме. Не считать общий персонализированный поток доказательством отдельной выдачи для каждого резюме. Исследование без отправки откликов и без изменения резюме.

## Уже установлено

- При чтении аккаунта 28.10.2026 инструмент `resumes` вернул четыре резюме: три с заголовками «Ведущий Python-разработчик / Tech…», «Senior AI Engineer / Python-разраб…», «Senior Python Backend разработчик» и ещё одно «Senior Python / AI Engineer | Zero…». Это противоречит прежнему предположению об одном резюме; выяснить, какие три соответствуют рабочим вариантам, их видимость и статус, прежде чем применять. Не удалять и не менять четвёртое автоматически.
- `suitable_vacancies` в подключённом MCP не имеет параметра ID резюме и в проверке вернул шесть показанных вакансий из заявленных 822. Установить, какое именно резюме и какие фильтры использованы, нельзя по этому выводу. Наличие общего количества не доказывает доступность всех страниц или фильтра «сегодня».
- `recommended` также не принимает ID и описан как общая персональная лента. `search` принимает поисковый текст и период, но не ID резюме; проверочный поиск Python с периодом в день 28.10.2026 вернул 403 на `chatik.hh.ru/chatik/api/chats`. Причина и возможность исправления не установлены; этот результат не доказывает, что все методы поиска недоступны.
- [База знаний hh](https://feedback.hh.ru/knowledge-base/article/0195) описывает рекомендации, доступные через список и страницу резюме, а также общую ленту, выбирающую резюме по собственным правилам. Это основание исследовать путь по конкретному резюме, но не доказательство доступного программного интерфейса, полного списка или сегодняшнего фильтра.
- [Документация API](https://github.com/hhru/api/blob/master/docs/vacancies_for_applicant.md) описывает `suitable_resumes_url` для поиска подходящих резюме к уже найденной вакансии. Это обратное направление, а не доказательство метода поиска вакансий по резюме. Документированный `resume_id` в API вакансий конкретного работодателя относится к его отдельному методу и не доказывает глобальный поиск.

## План проверки и сравнения

1. Сопоставить три утверждённых варианта с реальными ID, не раскрывая токены и не меняя данные. Уточнить опубликованность/видимость и проверить, как она влияет на подбор.
2. В интерфейсе hh открыть «подходящие вакансии» из каждого резюме и сравнить целевые адреса, фильтры, количество, порядок и образцы ID. Сначала документировать наблюдения; одинаковые результаты сами по себе не доказывают общий поток, а разные не доказывают полноту. Проверить, передаётся ли идентификатор резюме и сохраняется ли при фильтрации по дате и перелистывании.
3. Изучить локальные реализации MCP и доступные официальные интерфейсы: где формируется запрос, какие параметры доступны, почему общий MCP ограничивается шестью строками и откуда берётся 403 при поиске. Отдельно выяснить возможность исправить зависимость поиска от недоступного списка чатов, не обходя ограничения hh. Проверить доступ и условия на конкретном аккаунте; внутренние интерфейсы не считать стабильным API.
4. Если доступен адресный поиск, выполнить небольшую read-only проверку по каждому из трёх ID: сегодня по Europe/Moscow, сортировка, пагинация, реальные даты публикации, перекрытие и устойчивость после повтора. Сохранить время, метод, ID резюме и ID вакансий, счётчики и ошибки без секретов. Для подтверждения привязки проверять параметры и результаты, а не только отличия списков. Сравнить с интерфейсом и отметить ограничения видимости и повторных публикаций.
5. Если адресного способа нет, проверить альтернативы: отдельные сохранённые поисковые запросы по трём направлениям либо общий поиск с последующим локальным рейтингом всех резюме. Сравнить покрытие, доступность фильтра «сегодня», пагинацию и качество на небольшой выборке. Это запасные варианты, не эквивалент рекомендаций hh по резюме.
6. Оформить таблицу доказательств: способ, персонализация и привязка, дата, количество/пагинация, доступ, ограничения и побочные действия; отдельно указать неподтверждённое. Согласовать выбранный способ и порядок устранения ограничений до разработки конвейера. Если второй и третий профили ещё не готовы или проверка блокируется 403, зафиксировать предварительный результат и оставшиеся проверки.

## Критерий готовности

Подтверждён и выбран доступный способ получения сегодняшних вакансий по каждому рабочему профилю, либо явно согласована альтернатива. Понятны полнота страниц, источник даты, влияние видимости резюме и поведение при ошибках. Никакие рекламные оценки совпадения или число результатов не заменяют проверку.
