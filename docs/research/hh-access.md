# Исследование доступа к hh

Дата: 29 октября 2026. Исследование предварительное: проверка аккаунта заблокирована сетевой SSL-ошибкой. Изменений в hh и отправок не выполнялось.

| Вопрос | Что установлено | Статус |
| --- | --- | --- |
| Q-01: рабочие резюме | MCP `resumes` и `whoami` в этой итерации вернули `SSL: UNEXPECTED_EOF_WHILE_READING`. Данные о четырёх резюме из исследования 28 октября — исторические. Текущее соответствие трём профилям не проверено. | Открыт до восстановления доступа |
| Q-02: поиск по резюме | Обёртка `suitable_vacancies` вызывает страницу `/applicant/resumes/suitable_vacancies` без ID резюме, получает массив `relatedVacancies.vacancies` и не выполняет пагинацию. Шесть строк — то, что вернул этот массив при прошлой проверке, а не доказанный предел API. Привязка к резюме и полнота выдачи не доказаны. | Открыт; проверить браузер и реальные страницы после восстановления доступа |
| Q-02: текстовый поиск | В `server.py` функция `t_search` сначала вызывает `hh.search`, затем `applied_vacancy_ids`, чтобы пометить отклики. Последний объединяет текущие переговоры и `lost_negotiations`, зависящие от `chats()`. Поэтому 403 списка чатов может сорвать выдачу даже при успешном поиске. Сам `hh_client.search` работает отдельным вызовом поиска; его фактическая доступность в этой сессии не проверена. | Подтверждено чтением кода; прямой read-only тест отложен из-за SSL |
| Q-06: история | Обёртка `server_limited.py` не предоставляет методы истории и чатов. В клиенте есть чтение переговоров с пагинацией, а потерянные отклики восстанавливаются через чаты. Прошлая проверка списка чатов вернула 403; полнота архива неизвестна. | Частично установлено, нужны проверки аккаунта |
| Q-06: формы и письмо | По официальной документации hh `test_required` означает невозможность отклика через API на вакансию с обязательным тестом. Локальные записи от 27 октября сообщают об успешно перечитанном письме одного отклика и отдельной ошибке кодировки; в текущей итерации запись не тестировалась. Полное выявление анкет до отправки не доказано. | Неизвестные формы оставлять ручными |
| Q-07: лимиты | Официальная документация описывает ошибку `limit_exceeded`, но найденный раздел не устанавливает универсальный числовой предел для конкретного аккаунта. | Рабочий лимит не подтверждён; пилотные 5/15 — согласованные настройки, а не лимит hh |
| Q-09: Telegram | Данные переданы владельцем и сохранены локально; связь с ботом и личный чат в этой итерации не проверялись. | Проверить при реализации |

## Источники и код

- [Официальные ошибки hh](https://github.com/hhru/api/blob/master/docs/errors.md) — `test_required`, `already_applied`, `limit_exceeded`.
- [Документация соискателя](https://github.com/hhru/api/blob/master/docs/vacancies_for_applicant.md): `suitable_resumes_url` относится к поиску резюме для найденной вакансии, не к подбору вакансий для заданного резюме.
- [Официальный поиск вакансий](https://github.com/hhru/api/blob/master/docs/vacancies.md) ссылается на OpenAPI; применимость к аккаунту и пагинация не проверены.
- Изучена локальная интеграция antalez/hh-cv-mcp, commit `a0b72fb`: `server.py`, `hh_client.py`, `LICENSE.md`. Лицензия PolyForm Noncommercial 1.0.0; код не копировался и не запускался. `server_limited.py` только регистрирует выбранные методы и импортирует код клиента.

## Следующий шаг

Восстановить сетевой доступ и повторить read-only проверку аккаунта, затем сопоставить три резюме и проверить адресные рекомендации, фильтр дня и страницы. До результата нельзя утверждать, что подходящий источник найден или история полная. Не отправлять отклики и не менять резюме в ходе исследования.
