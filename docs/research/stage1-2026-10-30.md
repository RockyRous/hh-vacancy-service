# Первый этап: фактические проверки 30 октября 2026

Получены актуальные снимки трёх резюме hh: Senior Python Backend разработчик, Senior AI Engineer / Python-разработчик и Ведущий Python-разработчик / Tech Lead; они соответствуют локальным профилям. Снимки хранятся локально в `data/stage1-probe.json`, в Git их нет. Подготовлены четыре коротких локальных письма. Оценка v9 на ранее размеченных 26 определённых вакансиях совпала с разметкой по допуску и выбору профиля; четыре пограничных случая не включены. Выборка небольшая и использовалась при настройке.

На свежей выдаче найден ложный допуск вакансии Middle Backend (Rust/C++), где Python указан только для вспомогательных и старых сервисов. В v9 заголовки с Rust/C++ без Python ограничены ниже порога; проверка этого случая добавлена в тесты.

Прочитаны шесть страниц текущих откликов: 110 разных ID, страницы получены полностью. Это не подтверждает полноту архивов и скрытых откликов. Ни одна из трёх выбранных свежих вакансий не оказалась в прочитанном списке. У одной в форме найдено поле `task_`; у двух других форма `vacancy_response` содержит только служебный скрытый `_xsrf`. Это показывает различие страниц, но не доказывает отсутствие иных вопросов или внешней формы, поэтому эти две вакансии пока имеют статус `unknown`. Тексты и поля форм остаются локально.

Реализован транспорт одного POST на `/applicant/vacancy_response/popup` без повторов и переходов, с UTF-8 письмом. Подключён к механизму резервирования и проверки письма по ID чата из ответа. Автоматические тесты используют имитацию транспорта; новый код ещё не проверен живой отправкой. Значение `success` в ранее наблюдённом ответе не сохранилось, поэтому реальный формат подтверждения ещё предстоит проверить. Отсутствие подходящей вакансии с подтверждённым отсутствием анкеты и неполнота архивной истории пока блокируют отправку через новый механизм. Предыдущие ручные реальные отправки описаны отдельно в [исследовании](live-applications-2026-10-29.md).
